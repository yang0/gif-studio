# 三条失败演示的回归教训

之前曾生成三个约 30 秒的静音视频预览：AI 判断、GPS 卫星定位与通知打断专注。用户观看后反馈效果不合格。它们**不是成功案例**，不能拿来当作 README 的最终作品展示。

观察到的失败模式：

1. 同一条 GIF 被切片分配到多个不同叙事镜头，无法逐镜表达不同知识点。
2. GPS 的 GIF 内容偏离卫星定位机制；“主题相关”远不足以证明语义正确。
3. 一条视频大多数时间使用相同小动画框+顶部标题+底部字幕的固定模板；画面无实质推进。
4. 缺少真实配音，却容易被误称为已完成知识口播视频。
5. 4 镜头机械平均分成 7.5 秒，时长不是来自实际讲述。
6. QA 曾由制作脚本直接写成功状态，缺少独立技术/视觉验证。

对应回归门禁：

- director-plan.json 必须给出每镜的可见因果变化与前后连接。
- production/assets.json 绑定实际文件、分镜、导演版本、风格及生成提示词。
- production_preflight 默认拒绝没有充分理由的重复 GIF 字节。
- 正式审批需要 contact sheet 和实际语义/动作/风格/构图审查。
- 无声 MP4 在交付报告中明确标注为 qa_reviewed_silent_preview。
- CI 使用合成 GIF 测试工程逻辑，但不代表审核过真实 GPT 图像模型产出。

视觉质量无法全部由程序证明；该文档还需要真实人工复核的对照样片来丰富。
