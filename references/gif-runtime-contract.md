# GIF 工具运行契约

这是 gif-studio 的核心接口边界：生成了 prompt 文本不等于图像工具接收了该 prompt。

1. 编译独立镜头的 prompts/shot-N.txt。
2. 检查当前 Codex 的真实图像/GIF 工具签名，不能虚构接口。
3. 若工具支持显式文本 prompt：把编译出的完整 prompt 原样发送，并登记实际调用信息。
4. 若只支持从聊天上下文推断生成目标：必须标注 prompt_delivery=context_only_unverified，不能声称精确传递了编译 prompt；生成后仍须严格人工检查。
5. 不能从文件是否存在推断调用成功，更不能凭生成时的文档声明使用了指定模型。
6. 每次请求只制作一个镜头，不要在画面提示词中要求九宫格、故事板、拼图或 spritesheet；如工具本身需要帧网格用于 GIF 组装，那是工具内部参数，不是最终画面。
7. 尽量用具体的正向物件、动作和镜头描述。不要反复在生成提示词中提历史失败的图标名称，避免负面提示反而诱导图标。
8. 如工具支持静帧参考，先生成并检查主体终帧，再将其作为参考；若不支持，不能假装已使用参考图。

## 强制验收

- 实际文件格式为 GIF，至少五帧且有清晰变化与有效时长。
- **原生竖屏 9:16**，横屏 GIF 后期加黑边不能算通过。
- GIF 必须正确出现独立镜头中的主体和变化事件，且风格一致。
- 必须观看完整 GIF 与 contact sheet，不能自动编造语义通过。
- 若失败，只能定向调整或重设导演方案，禁止矢量动画替代。
- 必须有真实语音音频，才能宣称交付完成的有声口播视频。

先执行 scripts/verify_gif_asset.py，再执行 inspect_gif.py。技术合格只是视觉审核的前置条件。
